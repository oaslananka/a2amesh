# Repository Audit Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the evidence-backed repository audit gaps without weakening existing gates or publishing/deploying artifacts.

**Architecture:** Use the repository's existing governance, dependency-freshness, repository-evidence, CI, and agent-evaluation mechanisms rather than adding parallel systems. Changes stay reviewable on a dedicated branch; provider-backed checks are used where the Altunhost exec account lacks the pinned Node/pnpm toolchain.

**Tech Stack:** Node.js 24.16.0, pnpm 11.8.0, GitHub Actions, Renovate, repository evidence scripts, OpenCode skill evaluation.

**Spec:** UNIVERSAL AI-NATIVE REPOSITORY ENGINEERING AUDIT supplied for the 2026-09-04 audit.

## Global Constraints

- Do not deploy or publish as part of remediation.
- Do not weaken required CI/security checks to make the repository green.
- Prefer existing repository scripts and policy files over one-off automation.
- Keep each mutation reviewable and reversible.
- Treat unavailable local Node/pnpm as an environment limitation, not a repository defect.

---

### Task 1: Dependency security/freshness recovery

**Files:**

- Modify only dependency manifests/lockfile or repository dependency policy generated by the existing Renovate flow.
- Verify: `.github/workflows/dependency-freshness.yml`, `.github/workflows/security.yml`.

- [ ] Re-run `Dependency Freshness` on `main` to capture current provider evidence.
- [ ] Run the repository-managed Renovate workflow so vulnerability/OSV fixes are proposed using existing policy.
- [ ] Review generated dependency PRs and merge only fixes whose required checks are green.
- [ ] Re-run Dependency Freshness and Security; require audit and OSV gates to pass.
- [ ] Do not suppress advisories or lower severity thresholds.

### Task 3: Governance configuration/documentation alignment
