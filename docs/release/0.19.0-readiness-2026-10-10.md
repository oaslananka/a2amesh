# 0.19.0 stable candidate — release and onboarding assessment

**Observation date:** 10 October 2026. **Decision:** HOLD publication.
This is a candidate evaluation, not a release announcement or a request to
create a tag. The owner-triggered publish workflow and its explicit
`PUBLISH STABLE <tag>` confirmation must remain unchanged.

The prior published 0.18.2 first-use failures remain visible. The 0.19.0
artifact test used local file overrides to route six unpublished tarballs into
an otherwise fresh project. It passed the nine-layer golden-path verification
about 3.7 seconds after starting the local demo, after a roughly 5.7-second
cached installation. These are **automation timings**, not a fresh external
network installation, user-experience measurement or independent human study.
No npm version or dist-tag was changed.

## Release go/no-go conditions

1. Merge SDK refresh and generated scaffold install-policy changes through
   protected CI, including CodeQL, security checks, docs, release integrity,
   and live official JavaScript and Python SDK interoperability.
2. On **the same clean reviewed release commit**, rerun
   `pnpm run release:stable-ready` and record all 14 green gates.
   Any future failures are blockers; do not waive the clean-worktree check.
3. The six **unpublished candidate tarballs passed** isolated install,
   startup and nine-stage `pnpm verify` smoke tests with local file overrides.
   Repeat against exact final release artifacts and, after actual publication,
   from the npm registry; neither external reproducibility nor a five-minute
   human onboarding completion can be inferred from the cached local test.
4. Recruit actual independent developers with the [onboarding validation
   protocol](../development/independent-onboarding-2026-10.md). No fabricated
   participants or production adoption claims.
5. Owner separately authorizes the protected stable publication. After
   successful publication, verify npm `latest` and exact package
   versions, canonical tag, release assets/checksums, attestations/provenance,
   and refresh support and repository evidence.

A passing preflight does **not** automatically authorize tagging or
publishing. A candidate can be technically ready but still require the
explicit owner release decision.
